# DocView 不具合監査・修正記録

対象: `main` の `563094060805aa542075a25c9e857a5a6e611689`。
サーバー、CLI、全フロントエンドモジュール、画像解析、既存テスト、テーマ、依存関係、配布設定をレビューした。
以下は今回確認・修正した問題の一覧であり、未知の不具合が存在しないことを保証するものではない。

## サーバー・CLI

| 問題 | 対応 |
|---|---|
| 不正なパーセントエンコードの raw URL でサーバーが終了 | 400 応答に変換 |
| diagram API の `null`・不正な source 型でサーバーが終了 | JSON 形状・文字列型を検証 |
| 外部描画 CLI の stdin エラー・stderr 詰まり | エラーハンドラーと出力処理を追加 |
| 検索・backlinks・tree・gallery・custom CSS の外部 symlink 漏洩 | 公開ルート内への realpath 解決を検証 |
| IPv6 URL の角括弧によりリモート取得失敗 | 接続ホストを正規化 |
| IPv4-mapped IPv6 と link-local 範囲の private 判定漏れ | 対象表現と範囲を修正 |
| OS opener 不在でプロセスが終了 | 非同期起動失敗を API エラーへ変換 |
| TCP チャンク境界で日本語 JSON が破損 | バイト列結合後に UTF-8 復号 |
| JSON 本文のサイズ上限が文字数依存 | バイト数で制限 |
| ZIP の生成連番と実ファイル名が衝突 | 全エントリーを一意化 |
| `.docviewignore` の `?` による不正な正規表現 | 1 文字ワイルドカードへ変換 |
| `.env` の変更がライブ更新されない | 対象の隠しファイルを監視 |
| 巨大な remote サイズ指定が上限を無効化 | 安全な整数を検証 |
| stdout 内の URL による誤ったブラウザー起動・重複起動 | IPC の ready 通知を使用 |
| Windows の `start` を実行可能ファイルとして起動 | `explorer.exe` を使用 |
| CLI 終了時の子プロセス残存 | SIGINT / SIGTERM を伝搬 |
| 病的な正規表現が HTTP イベントループを停止 | Worker へ隔離し 1 ファイル 1 秒で打ち切り |

主な回帰テスト: `tests/server-audit.test.mjs`。

## テーマ・依存関係・検証

- 既存コントラスト検査の 11 失敗を修正。半透明色を背景と合成して検査し、30 テーマ × 10 項目を確認する。
- DOMPurify、markdown-it、Mermaid、Vite と推移依存を互換範囲で更新。固定依存環境の `npm audit` は 14 件から 0 件。
- C2PA を任意依存にし、ネイティブ導入失敗時も閲覧とバイト走査を利用可能にした。
- npm の固定依存を `npm-shrinkwrap.json` で管理する。
- Node の単体テストと Playwright のテスト探索を分離する。
- GitHub Actions に Node 20.19.0 / 22 のインストール・ビルド・単体・コントラスト・E2E 検証を追加する。

## 検証上の制約と残件

- ローカル環境では Chromium が起動時に SIGTRAP で終了し、接続済みブラウザーから localhost へのアクセスも拒否された。ブラウザー E2E の結果は PR の GitHub Actions 結果を参照する。テスト登録・型チェックの成功だけを E2E 成功として扱わない。
- Windows / macOS の OS アプリ起動は実機未検証。
- HTML 撮影では読み取り可能な Canvas を画像として保持する。CORS で読み取り不能な Canvas、closed Shadow DOM、属性に反映されないフォーム状態は完全には保持できない。CSP 等で応答を得られない場合は元 HTML の安全な描画へフォールバックする。
- この検証環境の npm 11.9 では、最終コミットを GitHub または tarball から別プロジェクトの依存として導入すると、同梱 shrinkwrap の修正版解決が適用されず、sharp 0.34.3 / xmldom 0.9.10 が再導入された。ソース・tarball・導入後の shrinkwrap の一致と、実際の node_modules の版を確認した。audit 0 件はリポジトリの `npm ci` 環境に限定される。固定依存を使うにはチェックアウトで `npm ci` 後に `node bin/mdv.mjs /path/to/documents` を実行する。上流固定依存の解消は残件。
- C2PA native が利用できない環境では暗号署名の検証は行えない。縮退経路は単体テストで確認した。
